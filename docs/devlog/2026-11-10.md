# 2026-11-10: IPC endpoint handoff and revocation

On the existing single-CPU scheduler, a timer interrupt could run another task
after an endpoint capability was checked but before send/receive entered the
scheduler. A different task could revoke and reuse the endpoint in that interval.
Similarly, capability mutation could release the capability lock before its
waiters were woken, allowing retyping to race the deferred wake-up.

Send/receive now keep maskable interrupts disabled across capability resolution
and scheduler handoff. CSpace invocation and each teardown operation keep them
disabled from mutation until pending endpoint aborts are flushed. The capability
lock is still released before the scheduler lock is acquired. This is a
single-CPU rule and not a general SMP, NMI, or spawner-authorization solution.

A ring-3 QEMU test records interrupt state at both boundaries. Before the fix it
observed enabled interrupts on both send and receive and failed. After the fix
it passed in debug and optimized self-test kernels. Four independent negative
controls removed send, receive, invoke and teardown guards; each failed the
intended handoff assertion. A full debug/release boot matrix was also run with
the production fix. See the hosted CI run for the final committed revision.
