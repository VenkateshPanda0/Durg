# 2026-11-10: IPC endpoint handoff and revocation

On the existing single-CPU scheduler, a timer interrupt could run another task
after an endpoint capability was checked but before send/receive entered the
scheduler. A different task could revoke and reuse the endpoint in that interval.
Similarly, capability mutation could release the capability lock before its
waiters were woken, allowing retyping to race the deferred wake-up.

Send/receive now keep maskable interrupts disabled across capability resolution
and scheduler handoff. CSpace invocation and each teardown operation keep them
disabled from mutation until pending endpoint aborts are flushed. The capability
lock is still released before the scheduler lock is acquired. This is a
single-CPU rule and not a general SMP, NMI, or spawner-authorization solution.

A ring-3 QEMU test records interrupt state at both boundaries. Before the fix it
observed enabled interrupts on both send and receive and failed. After the fix
it passed in debug and optimized self-test kernels. Four independent negative
controls removed send, receive, invoke and teardown guards; each failed the
intended handoff assertion. A full debug/release boot matrix was also run with
the production fix. See the hosted CI run for the final committed revision.

## Notification signal/wait and precise revocation

Implemented single-CPU notification signal and wait, including read/write rights,
FIFO waiters, full-width capability badges, zero-badge signals, coalescing, and
wake-up with `Aborted` when the object is revoked. The user ABI returns the badge
in `rdi` so its high bit cannot be confused with an error in `rax`.

The former endpoint-abort bookkeeping collected the lowest and highest destroyed
addresses. It could therefore abort an unrelated waiter between those addresses.
The kernel now snapshots at most one waiting address per thread while interrupts
are disabled and records only exact matches from destruction callbacks. It releases
the capability lock before acquiring the scheduler lock. A kernel regression
uses three waiters and synthetic destruction records at the outer addresses to
check the middle waiter survives; another test revokes a real notification.

Host capability property tests, a ring-3 capability demo, FIFO/wake/revocation
self-tests, and debug and release QEMU self-test kernels passed locally. This is
not IRQ delivery, DMA isolation, SMP support, or completion of M10/M11.

A dedicated ring-3 waiter now tests blocking delivery of a high-bit badge,
revocation while blocked, and stopping a blocked user task. Each scenario checks
that frames, reserved blocks, and scheduler waiters are reclaimed. The debug and
optimized self-test kernels each passed all 112 tests; these targeted runs selected
only the self-test boot variant.
