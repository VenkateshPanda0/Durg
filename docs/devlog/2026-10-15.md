### Spec findings that changed the design
- Base revision 3 makes the HHDM restrictive. Only usable, bootloader-reclaimable, kernel/modules and framebuffer regions are mapped. **ACPI tables are not**, so the RSDP address (physical) must not be dereferenced through the HHDM. M2 records the address only. M3 maps it itself.
- Memory map guarantees (sorted by base; usable and bootloader-reclaimable entries 4 KiB aligned and non-overlapping) are now checked by self-tests.

## M3 (part 1): CPU structures, exceptions, PIC, ACPI

### Done
- `durg-acpi` crate: RSDP, RSDT/XSDT and MADT parsing, pure and host-tested (17 unit tests, including malformed tables).
- GDT with a TSS and an IST1 stack for the double fault; IDT with gates for vectors 0-31; assembly entry stubs (stable Rust, no x86-interrupt ABI); a `TrapFrame` and a dispatcher with diagnostics (vector, name, error code, RIP, CS, RFLAGS, RSP, SS, registers, and CR2 with decoded error bits for page faults).
- Legacy 8259 PIC remapped and fully masked.
- ACPI discovery in the kernel (RSDP, then XSDT, then MADT), after checking the memory lies in an ACPI region the bootloader mapped.
- Self-tests: 15 (was 7). New ones: base revision, RSDP, MADT, local APIC present, GDT/TSS loaded, IDT loaded, PIC masked, breakpoint returns, page fault caught with correct CR2 and error code, an HHDM probe that must not fault.
- A new `double-fault` boot variant.

### Verified (real output)
- `cargo xtask test` and `cargo xtask test --release`: `boot test: PASS (4 variants)`, `selftest: all 15 tests passed`.
- Double fault: `EXCEPTION: Double Fault (vector 8)`, handler stack `0xffffffff80015070` inside the IST1 range `0xffffffff80011120..0xffffffff80015120`, `double fault handled on the IST stack`, exit status 33.
- **Negative control:** with the IST entry removed from the double fault gate, the same variant ended with `QEMU exit status: Some(0)` (a silent triple fault) and failed. Restored afterwards.
- MADT on QEMU: RSDP revision 2 via XSDT, local APIC `0xfee00000`, 1 CPU, I/O APIC id 0 at `0xfec00000`, 5 interrupt overrides.
- `cargo test -p durg-acpi`: 17 passed. `cargo fmt --check` and `cargo clippy -D warnings` clean for all four kernel feature sets, xtask and the acpi crate.
- Unsafe: 18 blocks in about 2,000 kernel lines (including test code): acpi 1, gdt 2, idt 1, x86_64 mod 7, trap 4, limine 3.

### Decisions made this session (small and reversible, flagged for the owner)
- Kernel requests Limine **base revision 4** (maps ACPI tables in the HHDM, RSDP virtual).
- Pinned bootloader bumped from **v9.6.7 to v10.8.5** because v9.6.7 supports revisions up to 3 only. Revert by changing `LIMINE_TAG` in `xtask/src/main.rs`.
- Running below revision 4 is a warning (ACPI unavailable), not a failure. Only an untouched tag is fatal.

### Mistakes
- First treated the bootloader's revision fallback as fatal. Corrected against the spec.
- A host test helper summed the wrong byte range for the RSDP's two checksums (test bug, parser was right).
- A debugging `grep` hid the kernel output because it shares a line with the bootloader's. Read raw output first.

### Not verified
- CI for this work has not run.
- A genuine stack overflow (needs a guard page, M5). The double fault test corrupts `RSP` instead.
- Behaviour under KVM, and real hardware.
- Exceptions other than breakpoint, page fault and double fault are handled by the generic fatal path, which prints diagnostics but is only exercised indirectly.

### Waiting on the owner: LAPIC timer
The local APIC timer needs register access. Evidence gathered:
- xAPIC registers are MMIO at physical `0xfee00000`, which is not in the bootloader's memory map, so it is not mapped.
- x2APIC (MSR access) would avoid mapping, but this QEMU CPU model reports `x2APIC no`, and QEMU 8.2.2 software emulation does not support it at all (`TCG doesn't support requested feature: CPUID.01H:ECX.x2apic`, for both `-cpu max` and `-cpu Haswell`). It could work under KVM but not in CI.

Options, with a recommendation in the session summary: (A) a tiny page-table mapper now, (B) move the timer after M5, (C) x2APIC only under KVM.
