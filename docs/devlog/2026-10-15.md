### Spec findings that changed the design

## M4: physical memory manager

### Done
- `durg-pmm` crate (`#![forbid(unsafe_code)]`): bitmap frame allocator with two bitmaps (managed and free) giving three states (not ours, free, allocated). `free` refuses frames out of range, never owned, or already free. `check_invariants` verifies five invariants.
- Host tests: 12 unit tests plus a model-based property test (512 cases, up to 300 operations each) against a `BTreeSet` reference model. `proptest` is a dev-dependency only.
- `mm::frame`: builds the pool from the Limine memory map (usable RAM above 1 MiB only), puts the bitmaps in the first usable region that fits, covers frames only up to the highest usable address (15 KiB instead of 32 MiB), re-entrancy guard, `alloc_frame`, `alloc_zeroed_frame`, `free_frame`.
- Boot now prints `PMM: 52835 frames (206 MiB) managed ...` and runs an allocate/free round trip.
- `mm::paging` now takes page-table frames from the allocator. The four-page boot pool from M3 is removed.
- `lapic::init` verifies its mapping by walking the page tables back (this also gives `translate` a runtime use).
- 7 new self-tests (32 total): totals vs an independent calculation, usable/distinct/aligned/outside-bitmaps, double free and foreign frames, zeroed frames are zero, 20,000-operation stress with unique per-frame patterns, exhaustion and recovery, page-table frames come from the allocator.

## M5: the kernel owns its address space

### Done
- `limine::capture`: the memory map, HHDM offset and RSDP address are copied into kernel memory at the start of boot and every accessor reads the copy. Nothing reads bootloader memory afterwards.
- `mm::paging` rewritten around `AddressSpace`: translate, `map_page`, `map_2m`, `map_range` (2 MiB pages where aligned), `unmap` (refuses to split a huge page, invalidates the TLB), `activate`. Any root works, not only the active one. `hhdm_reachable` reflects whichever tables are active.
- `mm::vm::take_over`: builds the kernel's own address space (image sections mapped with W^X from linker-script boundaries, direct map limited to RAM, bootloader memory and read-only ACPI), verifies it against the live tables, then loads CR3. The kernel image is not in the direct map, and neither are the framebuffer or reserved ranges.
- Kernel stack: 16 pages in PML4 slot 508 with an unmapped guard page below. Boot is now two stages, switching stacks between them.
- Double fault handler recognises a guard-page hit (CR2 or RSP in the guard page).
- `frame::reclaim_bootloader_memory`: adds the bootloader-reclaimable memory above 1 MiB to the pool, and refuses to run before the kernel is on its own page tables.
- New variant `stack-overflow` (feature `so-test`): real recursion into the guard page.
- Boot-time map/write/read/unmap round trip; `lapic::init` verifies its mapping.
- 13 new self-tests (45 total) and one more boot variant (5 total).
- ADR-0007 records the policy.
