## CI
- Run 1 (`5b61cc0`) failed: `Could not access KVM kernel module: Permission denied`. On the hosted runner `/dev/kvm` exists but is not openable, and `xtask` only checked that it exists. A bug in our harness, not the kernel.
- Fix `85671fd`: use KVM only if `/dev/kvm` can be opened read-write, else software emulation.
- Run 2 (`85671fd`) passed on a hosted `ubuntu-24.04` runner: fmt, clippy (kernel, xtask) and the boot test. The log shows `Durg kernel: boot ok (M1)`, `QEMU exit status: Some(33)` and `boot test: PASS`.
- The first CI failure could not be reproduced locally (this environment has no `/dev/kvm`, and root bypasses device permissions), so the fix was confirmed only by run 2.
