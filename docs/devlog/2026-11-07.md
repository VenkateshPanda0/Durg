# 2026-11-07: Reject spawner creation by retype

The pure capability core accepted `Kind::Spawner` in `retype`, although a spawner
is authority issued at boot rather than an object backed by untyped memory. The
kernel's `retype` dispatch already restricts accepted kinds, so this was not a
known route for a guest task to mint the authority. Keeping the core permissive
would nevertheless make that protection depend on every caller repeating the rule.

The core now rejects spawner retype with `BadSize` before modifying slots or the
untyped watermark. A regression test first failed against the previous code, then
passed after the check; the capability-operation fuzzer also asserts the rule.
This is defense in depth, not proof that spawner authority cannot be forged by
other paths. The interim spawner still allocates on behalf of tasks (ADR-0011).
